# Visual pass V3 (phone), iteration 1

Inspector: group V3, agent-browser session `mob1-V3`. Target: mock-data demo stack only, signed in as the mock founder.
Date: 2026-10-27. Nothing committed.

## Method and limits (read first)

- agent-browser has no touch flag and its `iPhone 15` preset reports `pointer: coarse` false. I attached a second CDP session that applies `Emulation.setDeviceMetricsOverride` (mobile, scale 3) and `Emulation.setTouchEmulationEnabled`. After that, `matchMedia('(pointer: coarse)')` and `matchMedia('(hover: none)')` both returned true, so the touch-target findings below are valid.
- Viewport: measurements were taken at 390x844. Screenshots were taken at 390x844 once the emulation was stable (1170 px wide). Early screenshots in the session were 393x852 because the agent-browser preset raced with my override; I discarded any capture whose size was not 390 wide when I judged it. One full-page capture tiled itself (race during resize) and was discarded.
- 375x812: I could set the viewport and read geometry, but the screenshot path kept reverting to 393 wide, so the 375 captures are NOT valid evidence. Only `innerWidth`, `scrollWidth` and element rectangles were read at 375 (Data room: no horizontal overflow reported once the viewport held). Treat 375 as unverified visually.
- 768x1024: `innerWidth` 768, `scrollWidth` 768, pointer coarse true for the Data room. The screenshot came back at phone size, so there is no tablet visual verdict.
- No on-screen keyboard exists in headless Chrome. Keyboard-covering-the-input checks were not possible; I can only say the inputs measure 44 px tall.
- layout-audit.js and geometry-audit.js were run on sign-in, chat, Integrations, Data room, Finance and the routine editor. Their "low contrast" hits on drawer rows are off-screen drawer content (false positives); I ignored them.
- Blocked or not reachable: passkey button on sign-in and passkey settings (the demo reports no passkeys; Settings has no passkey row), artifact share dialog, bot-built tools list, run history with rows ("No runs yet"), page-watch and check-in editors beyond the type menu (needs a created routine), typed UI blocks in a reply and Chief delegate progress (the scripted model asked for the "Share your chats and mail with the AI model" consent first; I did not press Allow because that is shared space state). Approval card was inspected without pressing Allow or Deny.

## Excellent as is (keep)

- Sign-in: 44 px fields, full-width Sign in, show-password toggle is a proper 44 px target.
- Drawer: every row and "..." is 44 px or more (measured; no target under 44), Pages above the space, Page agents fold, and "+6 more" is a full-width 44 px bar. The user menu and its items are comfortable.
- Integrations: search, 4 filter chips (all 44 px) and real brand logos; no horizontal scroll.
- Chat: single "..." per message, 44 px send, attach and mic, jump-to-latest pill, composer above the toast.
- Data room: folder tree is a dropdown ("All items") rather than a 180 px column, tile and row menus are always visible without hover, and the tile menu is a readable 160 px popover with 44 px rows. Preview is a centered card that fits (350 px wide). Failed files show a plain red reason and a Replace file button.
- Finance: KPI cards are equal-height pairs with outlines; Week/Month/Quarter/Year, Category/Vendor and "Show all N" are all 44 px; the Breakdown bar list is clear.
- Routine editor fields and selects are all 44 px; the when-to-run menu fits the screen.
- Settings dialog uses a section dropdown instead of a side rail.
